Protocole — Run #2 RTF (Corrosion M2)

Objectif : produire une 2ème trajectoire de corrosion à vitesse différente du Run #1, pour donner de la variété au modèle XGBoost (apprentissage de la loi de corrosion, pas mémorisation d'une courbe).

1. Conditions expérimentales

ParamètreRun #1 (fait)Run #2 (ce protocole)
AcideHCl brutHCl dilué 1:1 avec eau distillée
InhibiteurAucunAucun
FilFer ~2m Ø1.15mmFer ~2m Ø1.15mm (identique)
Vitesse attendueRapide (rupture 22h)~2× plus lente (rupture ~40-50h estimée)
Pourquoi diluer 1:1 ? Réduire la concentration de H⁺ ralentit la cinétique de corrosion. On obtient une vitesse différente sans acheter d'inhibiteur. C'est la variable expérimentale la plus simple à contrôler.

2. Préparation du fil (identique au Run #1)

  1. Coupe un fil de fer doux Ø1.15mm, longueur ~2 m (le plus proche possible du Run #1)
  2. Forme-le en U (les 2 extrémités sortent du bain par le haut)
  3. Nettoie le fil : frotte avec papier de verre fin puis dégraisse (alcool/acétone) pour enlever l'oxyde et les graisses — état de surface reproductible
  4. Connecte B et A dans les sockets femelles de jumper (comme Run #1)
  5. Mesure et note la résistance à sec au multimètre (devrait être proche de 1.29 Ω du Run #1 si le fil est identique)

3. Préparation de la solution

⚠ Sécurité acide — Toujours verser l'ACIDE dans l'EAU, jamais l'inverse (réaction exothermique, projections). Gants + lunettes + ventilation.
  1. Mesure un volume V d'eau distillée (ex : 250 mL)
  2. Ajoute lentement le même volume V de HCl brut dans l'eau (250 mL) → dilution 1:1
  3. Remue doucement, laisse refroidir à température ambiante avant immersion
  4. Note le volume total et, si tu as un pH-mètre, le pH réel (estimé ~1.3)

4. Câblage électronique — INCHANGÉ vs Run #1

Le montage reste exactement le même (validé au Run #1) :
VCC 3V3 → R_shunt 970Ω → B → [fil] → A → R_lift 970Ω → GND
HX711 A+ entre R_shunt et fil, HX711 A− entre fil et R_lift.
Calibration HX711_CAL_FACTOR = 33.7 conservée.

5. Lancement

  1. Flashe le firmware (déjà à jour avec le run_id Run #2) sur l'ESP32 via Arduino IDE → Upload
  2. Ouvre le moniteur série, vérifie :
    • Header affiche Run #2 RTF et le bon run_id
    • I ≈ 1.78 mA, Rx baseline cohérent (~1.3 Ω à sec)
  3. Note Rx baseline à sec dans ton cahier
  4. Plonge le fil dans la solution diluée (même profondeur que Run #1 : ~120 cm immergés)
  5. Note l'heure exacte de plongée
  6. Laisse tourner — 1 mesure / 30 s, envoi automatique vers Supabase sous le run_id Run #2

6. Suivi pendant le run

  • Surveille Rx de temps en temps (moniteur série ou dashboard)
  • Rx doit monter plus lentement que le Run #1 (c'est le but : vitesse différente)
  • Le run se termine à la rupture (Rx → plafond 98 Ω) ou si tu décides d'arrêter

7. Clôture du run

  1. Quand le fil casse (ou que tu arrêtes) : note l'heure de rupture
  2. Coupe l'alimentation de la sonde
  3. Marque le run comme terminé dans Supabase :
    UPDATE cr_runs SET status='done', ended_at=now() WHERE run_id='66e66c0a-...';
    (ou demande-moi de le faire)
  4. Nettoie les données debug/post-rupture comme pour le Run #1 (garde uniquement immersion → rupture)
  5. Sors et photographie le fil cassé (point de rupture) pour le mémoire

8. Après le Run #2

Tu auras alors 2 trajectoires à vitesses différentes. On pourra commencer à entraîner XGBoost en leave-one-run-out (apprendre sur Run #1, tester sur Run #2) pour voir s'il généralise. Idéalement viser 4 runs au total pour un modèle robuste.
